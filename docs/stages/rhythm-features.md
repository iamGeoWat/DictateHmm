# 环节 5：节奏特征

## 问题定义

**输入：** 分段结果。
**输出：** 段级别的时长、段间间隔、能量包络特征。
**作用：** 为下游候选匹配提供词边界、重音、轻声等线索。

## 为什么值得单独建模

声调序列本身歧义大（4 字声调序列空间仅 625，对应大量 4 字组合）。**节奏是几乎零成本就能拿到的额外信号**：

- **段时长**：轻声短；被强调的字偏长。
- **段间 gap**：词内 gap 短（50–150 ms），词间 gap 长（200 ms+）。这是分词先验。
- **能量峰**：用户可能无意识地把句子重音哼得响一点。

用户甚至能**主动**利用节奏：想强调某字时刻意拖长，想断词时刻意停一下。

## 可提取特征

| 特征 | 定义 | 对候选匹配的作用 |
|---|---|---|
| `duration[i]` | 第 i 段时长（ms） | 轻声判别、重音识别 |
| `gap[i]` | 第 i-1 段和第 i 段之间静音时长 | 词边界先验 |
| `energyMean[i]` | 段内平均 RMS | 重音权重 |
| `energyPeak[i]` | 段内峰值 RMS | 重音权重 |
| `pitchRange[i]` | 段内 F0 max-min | 声调表达强度，可反推用户是否"随便哼" |

全部轻量级，已有 F0 和 RMS 就能 O(n) 算出来。

## 如何使用

### 1. 词边界先验

把 `gap[i]` 离散化成三档：
- `< 120 ms` → 词内（强偏好同一个词）
- `120–250 ms` → 不确定
- `> 250 ms` → 词间（强偏好断词）

候选匹配时用作 Viterbi 的分词转移权重，或作为 LM 输入的 soft hint。

### 2. 轻声判别

如果段 `duration < 120 ms` 且 `energyMean` 低于前后段 3 dB 以上，概率性判为轻声，覆盖环节 4 的 F0 结论。

### 3. 重音提示

`energyPeak` 显著高于邻居时，把该位置字符的候选 LM 得分略偏向语义上被强调的词（例如疑问词、指代词）。MVP 不做，产品化阶段考虑。

### 4. 用户校准

第一次使用让用户哼一个已知序列（如"你好吗"），采集参考 duration/gap/energy 分布，后续特征都相对这个 baseline。

## MVP 选型

**特征 1（词边界先验）和特征 2（轻声）纳入 MVP，其余推迟。**

- 词边界：`gap < 150 ms` 视为词内，反之词间，二值信号送到候选匹配。
- 轻声：简单规则，参考上文。
- 重音、校准：P1，有时间再做。

## 升级路径

1. **数据驱动**：收集"哼哼—用户选中—真实分词"三元组，训练分词器（CRF / BiLSTM）。
2. **节奏输入法手势**：明确教用户"用停顿断词"，把节奏变成产品规范。
3. **多模态（触感）**：手机输入法 UI 上同步显示节拍气泡，让用户感知到自己节奏，形成正反馈。

## 开放问题

- 用户在真实对话中会不会忘记保持节奏？观察下来可能错误更多不是算法而是用户行为。
- 男女、慢速/快速说话者的 gap 阈值是否差异大？需要测。
- 段时长和重音特征的区分度有多大？可能在"都差不多"的情况下没有信号。
