# 环节 4：声调分类

## 问题定义

**输入：** 单段的 F0 序列（已去噪、归一化）。
**输出：** 声调标签 `1 | 2 | 3 | 4 | 5`（5 = 轻声）+ 置信度；可选 Top-2 alt。
**要求：**
- 准确率：干净哼哼 ≥ 90%（声调 2 vs 3 最易混）。
- 延迟：< 5 ms 每段。
- 浏览器可部署。

## 声调感知速记

- **一声**：高平调（55），F0 平直、偏高。
- **二声**：中升调（35），F0 由中到高递增。
- **三声**：降升调（214），典型先降后升，但在连读常变成"半三声"（21）。
- **四声**：全降调（51），F0 由高到低陡降。
- **轻声**：短促、低幅度，形状取决于前一个音节。

哼哼时没有元音、口腔共振几乎固定，**F0 曲线形状是唯一区分特征**。好消息是这比正常语音更"干净"——没有元音过渡引起的微颤。

## 方案对比

| 方案 | 精度（干净哼） | 训练数据 | 部署成本 | 代码量 |
|---|---|---|---|---|
| **规则：归一化 F0 的首末值 + 斜率 + 最低点位置** | 75–85% | 无 | 零 | ~50 LOC |
| DTW 模板匹配（每声调 3–5 个参考曲线） | 80–90% | 自录几条 | 低 | ~200 LOC |
| 小 CNN（32×32 F0 "图"） | 95%+ | 需要 ~数百带标签样本 | 中 | 中 |
| **ToneNet** 风格（CNN on mel-spectrogram） | ~99%（孤立音节） | 中 | 中 | 大 |
| F0 序列 Transformer（TNet-Full 2024） | SOTA（含上下文） | 大 | 大 | 大 |
| wav2vec2 / SSL 微调 | SOTA（含连续语流） | 很大 | 很大 | 大 |
| Pitch-Aware RNN-T（arXiv 2406.04595） | 研究级 | 大 | 大 | 大 |

### 关于数据

- **没有公开的"孤立声调"数据集**。通用做法：在 AISHELL-1 / AISHELL-3 上用 MFA / Kaldi 做强制对齐，切出带调音节。
- 注意：**普通语音切出的音节 ≠ 哼哼**。训练数据最好要有"真实哼哼"数据；若只用对齐出来的正常语音训练，域差可能显著，需要 domain adaptation 或用哼哼 fine-tune。
- 自己收集数据：让 5–10 人每人录 4 声各 20 遍，再加少量自然短语，得 400–2000 条即可训练小 CNN。

### 轻声与变调

- **轻声**需要时长 + 能量特征（F0 不可靠）——放到环节 5 节奏特征里联合判定。
- **连读变调**（如三声相连变二声）MVP 不建模，先认原始声调，让下游候选匹配去容错。

## MVP 选型

**规则分类器（v1）**，特征：

```
对单段 F0 做 log + z-score 归一化后：
  f_start  = 前 10% 帧 F0 中位数
  f_end    = 后 10% 帧 F0 中位数
  f_min    = 最小值
  f_min_pos = 最小值相对位置（0-1）
  slope    = (f_end - f_start) / duration
  curvature= 拟合二次曲线的二次项系数
  duration = 段时长

规则（大致）：
  if duration < 120 ms and energy_low:       → 轻声(5)
  elif |slope| small and f_mean high:         → 一声(1)
  elif slope > threshold:                     → 二声(2)
  elif slope < -threshold:                    → 四声(4)
  elif f_min_pos in [0.3, 0.7]:              → 三声(3)
  else:                                        → Top-2 with confidence
```

同时输出 Top-2 + 置信度，候选匹配环节把 Top-2 都扩展成候选。

**为什么不上 CNN：** MVP 先不要训练数据依赖，先跑通全链路。规则分类器肉眼调参快，做 baseline 也合理。

## 升级路径

1. **收集用户交互数据**（用户选中哪个候选 → 反推真实声调）→ 训练小 CNN（FreqToneNet 风格）。
2. **上下文声调建模**：把整句的 F0 序列一起喂 Transformer，处理变调。
3. **多任务**：同时预测声调 + 时长特征（轻声判别）+ 置信度。
4. **域迁移**：先在 AISHELL 对齐数据上预训练，再在哼哼数据上 fine-tune。

## 评测

- **孤立声调分类准确率**：自录 + 公开对齐数据混合测试集。
- **Top-2 覆盖率**：真实声调在 Top-2 中的比例（下游依赖这个）。
- **混淆矩阵**：2 vs 3、1 vs 4 的混淆是关键观察点。

## 开放问题

- 轻声的特征是否真的能仅靠时长+能量识别？哼哼没有 vowel，可能完全判不出。
- 用户之间的 F0 分布差异（男女 / 年龄）对规则分类器的影响，是否需要校准？（应该：第一次使用让用户哼一个已知序列校准音域。）
- 哼哼三声常被发得不完整（只降不升），规则阈值怎么设才兼容。
- 半三声、变调的处理时机：在本环节判还是留给候选匹配做容错？倾向后者。
