# MVP 执行计划

本文档是文档合集里唯一的"做什么"文档。其它文档是"选什么/为什么"。

## MVP 目标

**单一问题："闭嘴哼哼 + 上下文"能否在现实中被理解到可用程度？**

一切技术决策都服务于这个问题的最快验证，不做产品化工作。

## 成功/失败判定

见 [`overview.md`](./overview.md) 的"成功标准"。达不到三条之一 → 停工复盘。

## 阶段划分

两阶段：**先自己把链路搭起来跑通并调到可用，再拿给真实用户试。**

跳过"多模态 LLM 可行性验证"——MVP 选型不依赖 LLM，LLM 的结果也不能代表自建流水线的结果，做这一步等于绕远路。

### 阶段 1：端到端搭建 + 自评测迭代（7–10 天）

实现环节 1–7 的最简版本。**每个环节用最粗糙能跑的方案，先端到端打通；跑通后用自建评测集迭代到达标。**

#### 1a. 端到端打通（3–5 天）

任务清单：

- [ ] 项目脚手架：Vite + TypeScript + React（或原生 DOM，UI 最小）。
- [ ] 环节 1：`getUserMedia` + AudioWorklet，16 kHz mono PCM 流，按下录音松开结束。
- [ ] 环节 2：`pitchy` 逐帧 F0，中值滤波，log + z-score 归一。
- [ ] 环节 3：能量阈值 + ≥150 ms 静音切分。
- [ ] 环节 4：规则声调分类，输出 Top-2 + 置信度。
- [ ] 环节 5：算 duration / gap / energy，只用 gap 做分词先验。
- [ ] 环节 6：离线脚本用 jieba + python-pinyin 在 10M 字语料上建"声调序列 → 词候选"索引，打包成 JSON 送到前端。
- [ ] 环节 7：前端 beam search（beam=50），KenLM trigram（WASM）打分，取 Top-K。
- [ ] UI：麦克风按钮 + 输入框 + 候选列表 + debug 面板（F0 曲线、分段、声调序列）。

不做：
- 用户账号、设置、历史记录。
- 样式美化。
- 多平台适配（只要 Chrome 桌面版跑得动）。
- 任何需要大数据/训练的组件（例如 CNN 声调分类）。
- LLM rerank（作为阶段 2 的可选升级，不阻塞 MVP）。

**1a 出口标准：** 作者本人能哼出"你好"得到候选列表里有"你好"（不论位置）。证明链路没断，不代表质量。

#### 1b. 自评测迭代（4–5 天）

评测集：
- 作者自录：30–50 条哼哼 + 标注目标文本 + 上下文，覆盖 2–6 字常见短语、含轻声、含同调冲突（如全四声）。
- 小范围扩充：再找 2 人各录 20 条，验证不止作者自己能用。

指标：
- 端到端 **Top-5 命中率**（主指标）。
- 端到端 **延迟**（按下松开到出候选）。
- 各环节独立指标（见 [`architecture.md`](./architecture.md) "评测与回归"）——出错时用来定位是哪环。

迭代优先级（按 ROI 估计）：

1. 声调分类规则（阈值调整、Top-2 兜底）—— 便宜，立竿见影。
2. 候选索引语料规模（10M → 100M 字）—— 覆盖率直接提升。
3. 分段（若经常切错字数）—— 看实测，可能需要引入 VAD。
4. *（可选）* LLM rerank：如果基础链路到不了 60%，加云端 LLM 重排 Top-20 看能否拉上来。这是 MVP 内的"后备武器"，不是主路。

**阶段 1 出口标准：** 自建评测集 Top-5 命中率 ≥ 60% **且** 端到端延迟 ≤ 1 秒。达不到 → 复盘是"哼哼信息量不够"还是"工程没调好"，前者项目证伪，后者继续迭代。

### 阶段 2：真实用户试用（5–7 天）

- 找 3+ 位没参与开发的人，10 分钟内尝试用 DictateHmm 给朋友发一条消息。
- 简要引导（告诉他们要停顿、声调要分明），但不手把手教。
- 记录：能否完成、用时、错误次数、主观感受（好玩？累？实用？）。
- **不要自己试，自我验证没意义。**

判定：
- 有至少 1 人独立完成一条"有用的"消息 → MVP 成功，开始考虑产品化设计。
- 全员放弃 → MVP 失败，复盘原因（物理不行？学习曲线太陡？延迟？准确率？），决定是否换思路。

## 风险与应对

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| 哼哼本身信息量不够，任何算法都做不到 60% | 中 | 致命 | 1a 打通后立即用作者自录 10 条跑一次，若 <20% 提前证伪 |
| 规则声调分类准确率上不去（<70%） | 中 | 高 | 用 Top-2 兜底到候选层；或提前上 CNN |
| 候选索引太大/太慢 | 低 | 中 | 先词级，再字级；分片加载 |
| 用户不愿意停顿 150 ms | 高 | 中 | 加"节拍模式"兜底 |
| 浏览器麦克风/AudioWorklet 坑 | 中 | 低 | Chrome 桌面优先，其它后置 |
| 自建评测集过拟合（作者自己哼的当然准） | 中 | 高 | 阶段 1b 必须含至少 2 个非作者的录音 |

## 不在 MVP 范围

- LLM rerank（阶段 2 升级选项，见 [`stages/candidate-matching.md`](./stages/candidate-matching.md) Phase 2）。
- 旁路多模态 LLM（设计保留，实现推迟）。
- 任何"本地离线"能力（本地 LLM 见 candidate-matching Phase 3）。
- 移动端（手机浏览器可能跑得动但不优化）。
- 输入法系统集成（iOS Keyboard Extension / Android IME）。
- 用户个性化 / 账号 / 同步。
- 多语言（粤语、方言）。
